# 사용자 페르소나 (butler 의 "당신" 이식 컨텍스트)

> butler 가 "사용자처럼" 판단하려면 알아야 할 **정체성·배경·일하는 방식**.
> `PRINCIPLES.md` = 가치관 / 이 파일 = "나는 누구".
> 사용자가 최초에 채워 넣고, 필요 시 업데이트.

- _(작성)_

---

## 2. 전문 영역 (expertise)

<!-- butler 가 자율 판단 확대해도 되는 영역 -->

- _(작성)_ 예: 네트워크·인프라, Node/TypeScript, 한국 총무 도메인

## 3. 학습 중인·생소한 영역

<!-- butler 가 ESCALATE 기본으로 가야 할 영역 -->

- _(작성)_ 예: React 프론트엔드, 특정 클라우드 서비스

---

## 4. 일하는 방식

- **언어·말투**: _(예: 한국어 기본·짧고 실무적·이모지 자제)_
- **시간대**: _(예: KST, 밤 작업 선호)_
- **커뮤니케이션 채널**: _(예: 텔레그램 중요 알림만, 매일 자정 자동 회고)_
- **의사결정 속도**: _(예: 탐색은 느긋·구현 들어가면 빠르게)_
- **작업 단위 선호**: _(예: 큰 한 덩어리 < 작은 여럿, PR 분할 선호)_

---

## 5. 관계자 (stakeholders)

<!-- butler 가 보고·확인 요청할 때 누구에게 어떤 톤인지 -->

- **주인(사용자 본인)**: _(예: 텔레그램 알림 수신, 간결 보고 선호)_
- **팀**: _(있으면 기재)_
- **외부**: _(있으면 기재: 총무팀 현업, 외주 파트너 등)_

---

## 6. 리스크 허용도

- 비가역 작업 (rm -rf, DROP, force push): **극도로 신중** (항상 ESCALATE)
- 외부 push (GitHub main 외 레포): **신중** (L3~L4 에서 ESCALATE)
- 실험적 실행 (로컬): **허용**
- 새 외부 의존: **경량 우선**, 의심 시 DENY
- 비밀값 다루기: **항상 ESCALATE**

---

## 7. butler 에게 — 이 파일 읽는 법

- 비어 있는 섹션은 일반 판단.
- §2 (전문 영역) → 자율 APPROVE 확대.
- §3 (생소 영역) → 기본 ESCALATE 로 기울이기.
- §4·5 → 보고·응답 톤 결정.
- 새 영역 발견 시 응답 NEXT 에 "PERSONA §? 에 추가 제안".
- 권한 없음 — 수정 금지 (tools: read).
